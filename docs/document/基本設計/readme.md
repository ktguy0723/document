## プロジェクトのフォロソフィー
### 【PHI1】タスク遅延は全員でカバーする
- 遅延分は先行しているメンバーで巻き取りするなど、可能な限り作業時間に偏りが発生しないようにする

### 【PHI2】足並みを揃えて進める
- 作業を前倒しで進めることは推奨します
- ただし、前倒ししすぎると他機能との整合性の確認が十分にできないなど問題も発生する可能性が高くなります
- 作業速度より品質を重視して作業を進めていきます

### 【PHI3】レビューは個別業務観点、業務観点での全体整合性のチェックを主とする
- 誤記、処理不完全、フォーマット不正などの単純不良はない前提でレビューを行います

## 【WBS】スケジュール管理方針
### 【WBS1】進度ごとの作業方針
タスクの進度ごとに日々の作業を調整する
- 進捗が進んでいる ★
  - 遅延タスクのまきとり、担当分＋担当分以外の相互レビュー対応、追加タスク対応、に重点を置く
  - 上記がない場合は、前倒しで作業を進める
- 進捗がオンスケ
  - タスク消化、指摘対応、担当分の相互レビュー対応に重点を置く
- 震度が遅れている
  - タスク消化、指摘対応に重点を置く
  - 相互レビュー、遅延タスクの一部は作業が進んでいる人に依頼する

### 【WBS2】追加タスクの扱い方針
進捗100になったとしても以下の理由で追加タスクが発生します
- 顧客レビューなどによる指摘・要望対応
- 設計全体の整合性を合わせるための対応
- 課題解決に伴う設計見直し対応
これらは、課題運用のルールに従って対応します。

### 【WBS3】進度ルール
進度は以下のルールに従って対応します ★
- 0: 未着手
- 5: 着手開始
- 40: 記載進捗50%
- 70: 記載完了
- 75: 相互レビュー済（指摘あり）
- 80: 相互レビュー完了（指摘なしor指摘対応済）
- 85: 社内最終レビュー済（指摘あり）
- 95: 社内最終レビュー済（指摘対応済）
- 100: 完了

### 【WBS4】進捗入力タイミング
原則以下の2回お願いします
- 夕会の前
- 業務終了前 ★
  - 入力されていないと、明日の作業調整が困難になります
  - 必ずメンテしてから業務終了してください

## 【DOC】ドキュメント管理方針
### 【DOC1】 ドキュメント作成前の方針
ドキュメント作成前に以下を必ず目を通してください
- 画面イメージ：成果物のイメージや項目例を確認する
  - あくまでイメージです。参考程度で確認すること
- 機能構成図：どの機能、データを使用する想定か確認する
  - 設計の中で変更があれば合わせて修正すること
- 作成済の基本設計書：どのように記載すべきか確認する

### 【DOC2】 対象成果物
以下が成果物の対象になります
- 画面系
  - (個別)画面仕様書
  - データ仕様書（Front）
  - 画面遷移図 / 機能構成図 ★
- 機能系
  - (個別)機能仕様書
  - データ仕様書（Back）
  - 機能構成図 ★

### 【DOC3】 セルフチェックの方針
必ず以下の3つを実施したことを確認して進捗70%としてください
- [ ] 誤記、表記揺れがないか確認する（Copilotを使用してチェック）
- [ ] ぜんページ確認して編集漏れがないか確認する（テンプレートやコピペ元のままの記載になっていないか）

チェック完了後、相互チェックを依頼してください

### 【DOC4】相互チェックの方針
#### 相互レビューの目的
以下の目的を達成するために、「相互チェック」を実施します
- （レビューア）
  - 単純不具合の撲滅
- （レビューイ）
  - 担当以外の設計を理解する（属人化回避）
  - 良い設計を自分自身の設計に取り入れる

#### 相互チェックの方針
以下の順で実施してください。上の目的を達成するためだけに実施してください。

- 1. レビューアは、セルフチェックが完了したら、レビューイに連絡する
- 2. レビューイは連絡を受けたら、流し読みして不明な箇所がないか確認する（MAX 5分）
  - 誤記、記載不明瞭な箇所があれば指摘する
  - 設計の不明点は質問し理解する
- 3. レビューアは指摘を修正する
- 4. レビューイのOKが出たら以下を実施し最終レビュー依頼をする
  - フッターの署名欄にレビューア名/レビューイ名と記載
  - WBSの進捗をメンテする

- 上記の作業の中で意見が割れるようなことがあれば連絡してください

## 【REV】レビュー対応方針
### 【REV1】 レビュー指摘対応方針
以下の手順で対応します
- レビュー指摘表を確認する
- レビュー指摘を対応する
  - 対応方針で不明なところがあれば、都度相談してください
- レビュー指摘表に対応結果を記載し、WBSをメンテする
- 指摘完了した旨を連絡する

## 【ISS】課題運用方針
### 【ISS1】課題発生時の運用方針（担当用）
- 1. 不明点が出てきたら、質問する（担当→別担当+管理）
- 2. 解消しない場合、課題管理表に起票し全体に連絡する(担当)

### 【ISS2】課題管理方針（管理/担当用）
- 1. 課題が発生したら、期日と担当者を決める（管理）
- 2. 朝会・夕会で、課題状況をメンテする（管理）
- 3. 課題が解消したら、タスクに落とし担当を割り当て、朝会時に共有する（管理）
- 4. タスクが完了したら、課題管理表をメンテし全体に連絡する（担当）

## 【KNO】ナレッジ共有方針
### 【KNO1】全体機能機能説明会
- 全員に基本設計で決まった内容を定期的に共有する会を設ける（週1程度）
